## 2026-11-06: Project setup

**What I did**
- Configured Git: name, GitHub noreply email, `main` as default branch
- Created the repository and pushed it to GitHub
- Added .gitignore, README and LEARNINGS
- Worked on a feature branch for the first time in this project

**What I learned**
- GitHub's "keep my email private" setting only covers web operations.
  Commits from my own machine use my local Git config, so I had to set
  the noreply address there too.
- A simple rule of thumb for .gitignore: files generated by a machine
  don't belong in Git, files written by a person do.
- This explained the appsettings merge conflicts from a study project.
  The fix is to commit a template and ignore the local file.
- Daily candles that close at midnight UTC create short Sunday candles
  that can look like base candles. Closing the day at 17:00 New York
  time avoids this.

**Decisions and why**
- **One repo instead of several:** the backtester's data loading,
  engine and metrics can be reused by later research. I'll split it
  out if it ever needs to stand alone.
- **Public repo:** the project is meant to document my process,
  including the mistakes, not just the final result.
- **English everywhere in the repo:** commits and README are read by
  employers who may not speak Danish.
- **Ignore `data/` rather than `*.csv`:** it covers every file format,
  and doesn't block small test files that pytest needs.
- **Dukascopy hourly as main data, OANDA daily as reference:** Dukascopy
  has separate bid and ask prices. OANDA is what my manual backtest was
  done on, so it's the right benchmark for my own daily candles.
- **Reflective commit messages only for real decisions:** forced
  reflection on routine commits reads as forced. LEARNINGS.md is the
  place for session-level reflection.
